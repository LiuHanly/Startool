Overview

The StarTool project is an Android application and SDK produced by Glory Star Group. It serves as a test and demo platform for hardware devices (serial, bluetooth, GSIO components, etc.) and for computer vision features powered by Googles ML Kit. The repository contains both the app sources and several prebuilt native/AAR libraries.

The code base is written in Kotlin and Java, targets Android SDK 34, and uses Gradle 8.12.2 with Kotlin 1.8.22. Native code is built with CMake and packaged via JNI.

Key Features

  • Modular main menu with general tests, model demos, add-ons, aging tests, and live preview.
  • Bluetooth and serial communication utilities with logging and error handling.
  • Camera control and barcode scanning integrated with ML Kit (object detection, face/mesh, text recognition, and more).
  • APK update check and download service.
  • Multi-language support and runtime configuration.
  • Integration of multiple third-party AARs for GSIO, OTA, relay control, keypad, VOD, etc.
  • Helper libraries: Glide for images, Timber/Logger for logging, Room for local database, PermissionX, xpopup, etc.

    libs

    Library Composition (app/libs/) — Detailed Breakdown

    Below is a comprehensive breakdown of all third-party AAR modules with descriptions, features, integration steps, and usage examples:

    1. GSIOSdk-release.aar

    Features: Glory Star I/O SDK providing low-level hardware interface access (GPIO, I2C, SPI, etc.).

    Main Classes: GSIOManager, GPIOPin, I2CDevice, and others.

    Use Cases: Control LEDs, read/write sensors, drive peripherals.

    Integration Steps:

    1. Add to build.gradle: implementation files('libs/GSIOSdk-release.aar')
    2. Initialize SDK: val gsio = GSIOManager.getInstance(context)
    3. Configure GPIO: gsio.setPinMode(pinNumber, OUTPUT)
    4. Write data: gsio.digitalWrite(pinNumber, HIGH)

    Example Code:

    val gsio = GSIOManager.getInstance(context) gsio.setPinMode(17, OUTPUT) gsio.digitalWrite(17, HIGH) // High level Thread.sleep(1000) gsio.digitalWrite(17, LOW) // Low level
    2. keylibrary.aar

    Features: Keyboard/button input management library for handling physical hardware button events.

    Main Classes: KeyboardManager, KeyEvent, KeyListener.

    Use Cases: Listen for hardware key presses and execute custom actions.

    Example Code:

    KeyboardManager.getInstance().setKeyListener { keyEvent -> when (keyEvent.keyCode) { KeyCode.POWER -> { /* Handle power key */ } KeyCode.HOME -> { /* Handle home key */ } KeyCode.BACK -> { /* Handle back key */ } } }
    3. otaSdk-release.aar

    Features: OTA (Over-The-Air) firmware update SDK for remote device firmware updates.

    Main Classes: OTAManager, OTAUpdate, OTAProgress.

    Use Cases: Check firmware versions, download and install updates, monitor update progress.

    Example Code:

    val ota = OTAManager.getInstance(this) ota.checkUpdate("https://example.com/firmware") { available -> if (available) { ota.startUpdate("https://example.com/fw.bin", object : OTAProgress { override fun onProgress(percent: Int) { updateProgressBar(percent) } override fun onSuccess() { showToast("Update successful") } override fun onError(e: Exception) { Log.e("OTA", "Update failed", e) } }) } }
    4. lightStrip.aar

    Features: LED strip/RGB LED control library for managing addressable LED strips.

    Main Classes: LightStripController, LEDColor, Pattern.

    Use Cases: Set LED strip colors and play fade/blink effects.

    5. relaylibrary.aar

    Features: Relay control library for managing electromagnetic relays to switch power devices.

    Main Classes: RelayController, RelayState.

    Use Cases: Control main power, device switching, load driving.

    Example Code:

    val relay = RelayController.getInstance(this) relay.turnOn(1) // Turn on relay 1 Thread.sleep(3000) relay.turnOff(1) // Turn off relay 1
    6. vodlibrary.aar

    Features: Video-on-Demand (VOD) library for playing local or remote video files.

    Main Classes: VODPlayer, VideoFormat, PlaybackListener.

    Use Cases: Play demonstration videos, record test videos.

    Example Code:

    7. library-debug.aar

    Features: Debug tool library providing performance monitoring and log tracing capabilities.

    Main Classes: DebugPanel, PerformanceMonitor, LogCollector.

    Use Cases: Monitor application performance during development and collect logs.

    if (BuildConfig.DEBUG) { DebugPanel.getInstance(this) .enablePerformanceMonitoring(true) .enableLogCollection(true) .show() }
    Native Libraries (.so) — Architecture Support

    The project includes native libraries for the following ARM architectures under app/libs:

    • arm64-v8a: 64-bit ARM architecture for modern devices (recommended).
    • armeabi-v7a: 32-bit ARM v7, widely supported.
    • armeabi: Legacy ARM for backward compatibility only.

    Gradle automatically selects the appropriate architecture for the device. To restrict supported architectures:

    android { ndk { abiFilters 'arm64-v8a', 'armeabi-v7a' } }
    Complete Steps for Integrating All AARs into Other Projects
    1. Copy required AAR files to the libs/ directory of your target project.
    2. Copy architecture folders (e.g., arm64-v8a) to src/main/jniLibs/.
    3. Add all AARs to the dependencies block in build.gradle:
      dependencies { implementation files('libs/GSIOSdk-release.aar') implementation files('libs/keylibrary.aar') implementation files('libs/otaSdk-release.aar') implementation files('libs/lightStrip.aar') implementation files('libs/relaylibrary.aar') implementation files('libs/vodlibrary.aar') debugImplementation files('libs/library-debug.aar') }
    4. Declare required hardware permissions in AndroidManifest.xml.
    5. Sync Gradle and build the project.
    Critical Notes & Best Practices
    • Dependency Conflicts: Use gradle dependencies to check and resolve conflicts.
    • Permission Declaration: Hardware control AARs may require special permissions; declare them in the manifest.
    • Architecture Compatibility: Ensure your device supports the native library architectures in the AARs.
    • Version Updates: Regularly check for and update to newer versions of AAR libraries.

Known Limitations & Workarounds

  • PAD Series Legacy: Use legacy OTA and avoid advanced ML Kit features. Pin app to API 24 compatibility.
  • SPI on JAR/PAD: Not available; use I2C alternatives where possible.
  • UART Port Count: VegaX devices support 8 ports; configure carefully to avoid conflicts.
  • Thermal Constraints: VegaX with ML Kit segmentation may throttle under extended use; implement cooling intervals.
  • Root Access Requirement: All hardware interfaces mandate root privileges. Standard firmware by default provides this for authorized devices only.
  • Bluetooth Classic on VegaX: Requires explicit pairing; BLE is recommended for new integrations.
  • WiFi/Ethernet Switching: VegaX requires brief reconnection delay; implement 100ms wait between interface switches.
  • ML Kit Model Size: Bundled models consume ~150MB; ensure sufficient free storage before activation.

Testing & Validation Requirements

Before deploying to production, validate the following on your target device family:

  1. Architecture Match: Verify native libraries match device CPU (use adb shell getprop ro.product.cpu.abi).
  2. Root Access: Confirm root privileges and authorized firmware with adb shell su -c 'whoami'.
  3. Hardware Interfaces: Test GPIO, UART, RFID via provided examples.
  4. ML Kit Initialization: Verify all bundled models load without errors in logcat.
  5. Performance Baseline: Record baseline FPS for barcode scanning and face detection on your device.
  6. Thermal Test: Run heavy ML Kit workload for 30+ minutes; monitor for throttling.
  7. OTA Simulation: Test firmware update flow on staging firmware before production deployment.
  8. Memory Stability: Monitor RAM usage over 4+ hours of continuous operation.

RFID Control (glorystar-rfid-sdk.aar)

The RFID SDK provides comprehensive support for RFID card readers and writers, enabling contactless identification, data collection, and access control applications.

RFID Reader Supported Protocols

  • ISO/IEC 14443 Type A - Mifare Classic, Mifare Plus, DESFire
  • ISO/IEC 14443 Type B - Various industrial RFID cards
  • ISO/IEC 15693 - 13.56 MHz vicinity cards
  • FeliCa - Japanese IC card standard

Main Classes & Methods

RFIDManager Initialization & Lifecycle

import com.glorystar.rfid.RFIDManager import com.glorystar.rfid.RFIDCallback // Initialize RFID Manager val rfidManager = RFIDManager.getInstance(context) // Set card detection listener rfidManager.setRFIDListener(object : RFIDCallback { override fun onCardDetected(cardData: RFIDCard) { Log.d("RFID", "Card UID: ${cardData.uid}") Log.d("RFID", "Card Type: ${cardData.type}") Log.d("RFID", "Serial: ${cardData.serial}") } override fun onCardRemoved() { Log.d("RFID", "Card removed from reader") } override fun onError(errorCode: Int, message: String) { Log.e("RFID", "Error $errorCode: $message") } }) // Start RFID service rfidManager.start() // Stop and cleanup rfidManager.stop()

Reading Card Data

// Read entire card memory rfidManager.readCard { result -> if (result.isSuccess) { val cardData = result.data Log.d("RFID", "Card ID: ${cardData.cardId}") Log.d("RFID", "Block Data: ${cardData.blocks}") // Parse specific sector val sector0 = cardData.readSector(0) Log.d("RFID", "Sector 0 Key A: ${sector0.keyA}") } else { Log.e("RFID", "Read failed: ${result.error}") } } // Read specific block (Mifare Classic) rfidManager.readBlock(blockNumber = 4, keyA = byteArrayOf(...)) { blockData -> Log.d("RFID", "Block data: $blockData") }

Writing Card Data

// Write data to specific block val dataToWrite = byteArrayOf(0x01, 0x02, 0x03, 0x04, ...) rfidManager.writeBlock( blockNumber = 4, data = dataToWrite, keyA = byteArrayOf(...), callback = { success -> if (success) { Log.d("RFID", "Write successful") } else { Log.e("RFID", "Write failed") } } ) // Format/Erase card rfidManager.formatCard(keyA = byteArrayOf(...)) { result -> Log.d("RFID", if (result) "Card formatted" else "Format failed") }

Authentication & Key Management

// Authenticate with Mifare key val defaultKeyA = byteArrayOf( 0xFF, 0xFF, 0xFF, 0xFF, 0xFF, 0xFF // Default factory key ) rfidManager.authenticate( sectorNumber = 1, keyA = defaultKeyA, callback = { authenticated -> if (authenticated) { Log.d("RFID", "Authentication successful") // Proceed with read/write operations } } ) // Change key for specific sector rfidManager.changeKey( sectorNumber = 1, oldKey = defaultKeyA, newKeyA = byteArrayOf(0x12, 0x34, 0x56, 0x78, 0x90, 0xAB), newKeyB = byteArrayOf(0x12, 0x34, 0x56, 0x78, 0x90, 0xAB) ) { success -> Log.d("RFID", if (success) "Key changed" else "Key change failed") }

Card Enumeration & Type Detection

// Get all detected cards rfidManager.getAllCards { cards -> for (card in cards) { Log.d("RFID", "Found card: ${card.uid} (${card.typeString})") when (card.type) { RFIDCardType.MIFARE_CLASSIC -> { /* 1KB/4KB classic */ } RFIDCardType.MIFARE_PLUS -> { /* Modern secure Mifare */ } RFIDCardType.DESFIRE -> { /* Advanced DESFire cards */ } RFIDCardType.ULTRALIGHT -> { /* Low-cost Ultralight */ } RFIDCardType.ISO_B -> { /* ISO Type B */ } } } }

GPIO / UART / Wiegand (glorystar-hardware-sdk.aar)

The Hardware SDK provides comprehensive access to GPIO pins, UART serial ports, and Wiegand protocol for interfacing with industrial hardware, access control systems, and sensors.

1. GPIO (General Purpose Input/Output) Control

GPIO Pin Configuration & Operations

import com.glorystar.hardware.gpio.GPIOManager import com.glorystar.hardware.gpio.GPIOPin // Initialize GPIO Manager val gpioManager = GPIOManager.getInstance(context) // Configure pin 17 as output gpioManager.configurePin( pinNumber = 17, mode = GPIOPin.MODE_OUTPUT, initialState = GPIOPin.LOW ) // Write digital output gpioManager.digitalWrite(pin = 17, state = GPIOPin.HIGH) Thread.sleep(500) gpioManager.digitalWrite(pin = 17, state = GPIOPin.LOW) // Read digital input gpioManager.configurePin(pin = 23, mode = GPIOPin.MODE_INPUT) val inputState = gpioManager.digitalRead(pin = 23) // Returns HIGH or LOW // Set up input interrupt listener gpioManager.setEdgeListener(pin = 23, edge = GPIOPin.EDGE_RISING) { pin, state -> Log.d("GPIO", "Pin $pin state changed to: $state") }

PWM (Pulse Width Modulation)

// Configure PWM on pin 18 gpioManager.configurePWM( pin = 18, frequency = 1000, // 1 kHz dutyCycle = 50.0 // 50% duty cycle ) // Adjust brightness smoothly (0-100%) for (brightness in 0..100 step 10) { gpioManager.setPWMDutyCycle(pin = 18, dutyCycle = brightness.toDouble()) Thread.sleep(200) } // Stop PWM gpioManager.stopPWM(pin = 18)

GPIO Group Operations

// Write multiple pins at once (atomic operation) gpioManager.multiWrite(mapOf( 17 to GPIOPin.HIGH, 22 to GPIOPin.LOW, 27 to GPIOPin.HIGH )) // Read multiple pins val pinStates = gpioManager.multiRead(listOf(23, 24, 25)) pinStates.forEach { (pin, state) -> Log.d("GPIO", "Pin $pin: $state") }

UART Port Configuration

Integrated Hardware Control Example

Combining GPIO, UART, and Wiegand for a complete access control system:

// Multi-hardware integration example class AccessControlSystem(context: Context) { private val gpio = GPIOManager.getInstance(context) private val uart = UARTManager.getInstance(context) private val wiegand = WiegandManager.getInstance(context) init { // Initialize relay control via GPIO gpio.configurePin(17, GPIOPin.MODE_OUTPUT, GPIOPin.LOW) // Initialize door sensor via GPIO input gpio.configurePin(25, GPIOPin.MODE_INPUT) gpio.setEdgeListener(25, GPIOPin.EDGE_BOTH) { pin, state -> Log.d("Door", "Door sensor: $state") } // Initialize barcode via UART uart.openPort("/dev/ttyS2", SerialConfig(baudRate = 9600)) // Initialize Wiegand card reader wiegand.configure(WiegandConfig(d0Pin = 23, d1Pin = 24)) wiegand.setCardListener(::onCardScanned) } private fun onCardScanned(card: WiegandCard) { if (isAuthorized(card)) { // Unlock door via relay gpio.digitalWrite(17, GPIOPin.HIGH) Log.d("Access", "Door unlocked") Thread.sleep(2000) gpio.digitalWrite(17, GPIOPin.LOW) // Log access via UART to external system uart.write(0, "UNLOCK|${card.cardNumber}".toByteArray()) } } }

Hardware Troubleshooting & Best Practices

  • GPIO Signal Integrity: Use proper cable shielding and terminated bus lines to avoid noise interference.
  • UART Baud Rate Mismatch: Verify both sender and receiver use identical baud rates; mismatches cause data corruption.
  • Wiegand Pulse Timing: Ensure pulse duration meets hardware specs (typically 20-200 μs per bit).
  • Power Supply Stability: Fluctuating supply voltage can cause erratic GPIO/Wiegand behavior; use regulated power with adequate current rating.
  • Pull-up/Pull-down Resistors: Required for many GPIO and Wiegand implementations; consult hardware schematic.
  • Root Access Requirement: All hardware-level operations require root privileges; verify device firmware.
  • Resource Cleanup: Always call close() or release() methods in Activity/Service lifecycle to prevent resource leaks.
